# note-6: CANN 9.1 ES 构图接口官方参考（容器头文件精读）

来源：容器 `/usr/local/Ascend/cann-9.1.0/include/es/` + `include/ge/es_*.h`。
官网无 ES/es_* API 公开文档页（多次检索未命中），**本笔记以容器内头文件为唯一权威**，
语义推断处已标注。整理日期：2026-09-10。

## 1. 组织方式

每 op 一对头文件：C++ `es_Xxx.h`（inline 自由函数，namespace `ge::es`，返回
`EsTensorHolder`，输入 `EsTensorLike` 可隐式从 holder/标量构造）+ C ABI `es_Xxx_c.h`。
每目录聚合头 `es_<dir>_ops.h`。头标注 "GENERATED by bin/gen_esb"。

| 目录 | 头文件数 | 内容 |
|---|---|---|
| es_math | 583 | 基础数学/张量变换/归约/随机 |
| es_nn | 737 | NN 算子、量化、优化器、norm、通信融合 |
| es_transformer | 133 | PFA、RoPE、MoE、AllReduce+Matmul 融合 |
| es_cv | 141 | 检测/图像处理 |
| es_hccl | 27 | Hcom 集合通信 |

## 3. ES 建图流程（ge/es_graph_builder.h 等）

1. `ge::es::EsGraphBuilder builder("graph_name");`（析构自动 EsDestroyGraphBuilder）
2. 输入：`builder.CreateInput(index [, name [, dtype, format, shape]])` -> EsTensorHolder；
   常量 `CreateConst<T>(value, dims [, dt, format])` / `CreateScalar(...)` / `CreateVector(...)`；
   变量 `CreateVariable(index, name)`。图属性 `builder.SetAttr(name, v)`。
3. add op：直接调 `ge::es` inline 函数（`Add(x1,x2)`、`MatMulV3(...)`），owner builder 从输入
   推导，返回 holder 可链式组合。
4. IR 兜底：`ge::es::CompliantNodeBuilder(graph->GetGraph()).OpType("Xxx").Name(...).IrDefInputs/
   IrDefOutputs/IrDefAttrs(...).InstanceOutputShape/DataType/Format(...).Build()` -> ge::GNode。
   这是"localized raw-GE adapter"通道。
5. 出图：`EsGraphBuilder::SetOutput(tensor, index)`（static）+ `BuildAndReset()` ->
   `std::unique_ptr<ge::Graph>`；或 `BuildAndReset(outputs)` 自动按序。
6. 编译执行：`ge::Session` -> AddGraph -> CompileGraph -> LoadGraph ->
   ExecuteGraphWithStreamAsync（链路见 note-5 §3）。

**ES builder 无 SetInputs**（输入即 CreateInput 的 index）；`Graph::SetInputs/SetOutputs` 是
IR 层旧接口，ES 流程不用。

## 5. 对阶段 3 的直接修正

相对 note-3 的初步假设，本笔记更新三点：
1. **RMS_NORM 用 es_nn 原生 RmsNorm**，不做 Mul/Pow/Mean 分解（JittorInfer pre-#11 的分解
   方案仅作语义对照基准）。
2. **SILU 用 Swish(scale=1)** 而非分解。
3. ggml PERMUTE -> es Permute（C++ 属性 order，免建常量张量）；ggml TRANSPOSE ->
   es Transpose（perm 张量输入）或按维数选 Permute。轴序换算（ggml 倒序 vs GE 正序）
   在 graph-build 层统一处理。
