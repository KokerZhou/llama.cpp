# note-15: CANNGE 回退层次规范

> 用户落地口径（2026-10-09 重申）：**能原生原生，能 ES ES，能上卡上卡**。
> 例：Attention 有 FusedInferAttentionScore 这类优化实现就禁止用
> matmul+softmax 自拼；一切降级以"还在卡上"（GE 或 eager aclnn）为底线，
> CPU 仅全拒兜底。与下表层级的关系：L1a/L1b=原生档，L2=ES 档，L3-L5=上卡档，
> L6=兜底。

建立：2026-09-11。规范对象：CANNGE 后端"某张图/某个 op 落不了地时怎么办"的完整层次契约。
层次定义以 note-3 D1（2026-09-10 定稿）为权威，本文将其规范化为可执行条款并标注
当前实现状态。**本文与 note-3 冲突时以本文为准的部分仅限实现状态标注；层次语义以
note-3 为准。**

## 1. 层次总表

回退是三个正交轴的笛卡尔积，按优先级在积空间选点（note-3 D1）：

- 轴 A 节点实现：A1 原生 GE 算子（含同义变体）/ A2 ES 原语分解 / A3 自定义算子（hold）
- 轴 B 图拓扑：B1 整图一张 / B2 分段（>=2 张 GE 图）
- 轴 C 执行引擎：C1 GE 编译产物 / C2 eager aclnn / C3 CPU

| 级 | 名称 | 轴取值 | 触发条件 | 当前实现状态 |
|---|---|---|---|---|
| L0 | 静态能力门控（元层） | — | 调度器问 supports_op / 构建 plan 签名 | **已实现**：env 门 + 逐 op 静态校验（note-14 §2） |
| L1a | GE 整图·原生 | A1×B1×C1 | 所有节点静态支持 | **已实现**（窄 op 集） |
| L1b | GE 整图·同义变体 | A1'×B1×C1 | 首选 GE 算子本 SoC 不可用、有同义算子（attention 的 FIA/PFA 变体、matmul 变体等） | 预留：变体表未建；现例 MUL_MAT 用 BatchMatMulV3 顶替 MatMulV3（构建期定死，非运行时变体选择） |
| L2 | GE 整图·ES 分解 | A2×B1×C1 | 原生缺失、分解成分全静态支持 | **部分实现**：RMS_NORM/SILU 即以元语落地（note-6 §5） |
| L3 | GE 分段（段内 L1/L2） | B2×C1 | 整图 CompileGraph 失败且可定位嫌疑节点 | **预留，未实现**：当前编译失败 → FAILED plan → graph_compute 返回 FAILED 交调度器；分段编译错误解析、黑名单、段边界导出均未落地 |
| L4a | eager aclnn 单算子 | C2 | 段间填补节点有原生 aclnn | **以独立后端形式存在**（GGML_CANN）：由调度器把不支持的部分切给 CANN 后端，非 CANNGE 内部行为 |
| L4b | eager aclnn 等价组合 | A2×C2 | L4a 不可用、组合成分全可用 | **预留，hold**（见 §3） |
| L5 | 自定义 AscendC 算子 | A3×C1 | 仅当测量证明 L1b/L2/L4b 都不够 | **hold**（见 §4） |
| L6 | CPU 兜底 | C3 | 后端整体拒绝（supports_op=false） | **由调度器实现**（upstream ggml-backend），CANNGE 只负责正确拒绝 |

## 2. 各层职责与契约

### L0 静态能力门控

- 职责：在构图之前把"必败"的图挡在门外，让失败以 not-supported 形式出现而非运行时错误。
- 触发：supports_op 逐节点判定；graph_compute 入口再做一次全图预检（ggml-cannge.cpp:336-347）。
- 必须记录：拒绝原因走 GGML_LOG_ERROR（op 编号）；细分原因（dtype/shape/对齐/layout）
  当前未分级打印，属改进项。
- 误拒是设计允许的代价（静态表宁保守，note-3 D3）。

### L1/L2（整图命中层）

- 职责：整图一张 GE 图，编译产物进 plan cache；同签名直接复用。
- 触发：L0 全绿 → 构图 → AddGraphWithCopy → CompileGraph → LoadGraph → 执行。
- 必须记录：编译失败缓存 FAILED plan（防反复秒级编译，note-18 §2.4）；构建失败不缓存。
- L2 分解的代价已知：节点变子图、fp16 舍入差异；分解选择必须入 plan 签名（note-3 D1
  横切变量）。

### L3 图内局部回退（分段）——预留，当前未实现

- 设计职责：整图 CompileGraph 失败 → 错误解析（尽力）定位嫌疑节点 → 黑名单 → 按段
  切分（每段一张 GE 图，段内仍走 L1/L2）→ 段边界张量显式导出为零拷贝衔接的 device
  buffer（note-3 D1 遗留#2）。
- 段数上限非固定常数：由 HBM 预算动态决定；加载新 plan 前预算检查，不足先驱逐冷
  plan，仍不足放弃分段直降 L4（note-3 D6-2）。
- 当前行为（规范性描述现状）：编译失败即 FAILED plan，整图交回调度器；**禁止**在未实现
  分段时假装支持部分图。

### L4 eager ACLNN 层

- L4a 职责：CANNGE 不支持的节点由调度器切给 GGML_CANN 后端以 eager aclnn 执行
  （两后端独立共存，见 note-18 §1）。aclnn 支持集 != GE 支持集（note-3 D1），切分判定
  是调度器的 supports_op 机制自然完成的，CANNGE 无感知。
- 触发条件边界：某图 CANNGE 部分支持时，调度器 split 会产生跨后端 buffer 拷贝
  （H2D/D2H），这是 L4 层相对 L1 的主要代价，属调度器行为，CANNGE 不干预。

### L6 CPU 兜底

- 职责：所有加速器层都拒绝时由调度器切 CPU。CANNGE 的唯一义务是**诚实地返回
  false/FAILED**，禁止半支持状态（看似支持、执行报错）。

## 3. "aclnn 等价组合替换"扩展点（L4b，hold）

- 用户决策（2026-09-10 讨论，note-3 D1 L4b 行）：某 aclnn 不可用时，**优先**用等价
  aclnn 组合替换；实在不行再考虑手写算子或 CPU。
- 形态：A2×C2——eager 组合策略表驱动（如某单一算子缺、用多个 aclnn 拼等价语义），
  组合成分必须各自静态可用；代价为中间 buffer 访存与 k 倍 kernel 启动开销。
- 状态：**预留扩展点，hold 中**。前置依赖：组合策略表（无硬件时不可固化，需真机确认
  成分可用性）、与 L3 段边界的 zero-copy 衔接设计（note-3 D1 遗留#2）。落地前禁止在
  代码中留半成品组合路径。

## 4. 手写算子（L5 自定义 AscendC）——暂不考虑，hold

- 决策（note-3 D2，阶段 1-3 不实现）：理由三条——OPP vendor 包 per-SoC 架构编译、
  兼容性差，违背"后端可独立编译"；proto+tiling+kernel+打包四件套开发代价高；现有需求
  可被 L2（ES 分解）与 L4b（eager 组合）覆盖。
- 规范性表述：**暂不考虑**。设备强相关、兼容性差；预留可能性但接入层次未定
  （图内节点 vs 图外 eager 插件两层归属待商榷，note-3 D2 遗留），**hold 中**。
- 仅在"测量证明 L1b/L2/L4b 都不够"（justified by measurement）时由人工决策重启讨论。
- 事实备查：自定义算子是 GE 图内节点，GE 可做算子间调度/内存规划/边界融合（对自定义
  op 默认保守，fusion 信息需额外注册）；官方认可其为最后手段（T1 图开发指南
  atlasgraphug_24_0007，note-7 §1-3）。JittorInfer 的 RopeExtCustomV2 即此类且为构建期
  强制依赖，**禁止照搬**（note-1 §7-5）。

## 5. 层间转移控制与记录要求

层间转移表（note-3 D1）规范化为：

| 转移 | 决策主体 | 必须记录的内容 |
|---|---|---|
| L1→L2 | 后端（构图期，改静态表即回） | 分解策略选择入 plan 签名 |
| L2→L3 | 后端（编译期） | 错误码 + GEGetErrorMsg 文本（note-5 §6 要求打印文本非裸码）、失败节点候选集、黑名单条目 |
| L3→L4 | 后端（编译期） | 段边界张量清单、降级记录 |
| L4→L6 | 后端撤回 supports_op → 调度器重切 | 撤回原因 |
| 任意→L6（图外） | 调度器 | 调度器自身日志 |
| 数值回退（横切） | 后端（验证期） | 容差标注：降级实现上线前必须过 test-backend-ops 离线验证并建议进 CI，**运行时禁止**重复容差检查（note-3 D1 遗留#4） |

黑名单规范：粒度 per (SoC, op)，shape 相关失败进 plan 签名处理；黑名单与 plan 缓存
必须持久化（310 首次加载是能力学习的真正时刻，结果固化为缓存+黑名单，note-3 D1
时间线）。当前持久化机制未实现，列入待核实/待办。
